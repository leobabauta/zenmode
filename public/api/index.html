API

Read and write your zenmode tasks and notes from anywhere — a Shortcut, a shell script, a widget, or whatever you like to build. Generate a key in Settings, send it as a bearer token, and you’re done.

Getting a key

Open zenmode, go to Settings → Features → API, and generate a key. Keys start with zmk_ and are shown exactly once — copy it before you close the banner. Only a hash is stored, so a lost key can’t be recovered; revoke it and generate a new one.

Each key has a scope:

  • items:read — GET requests only.
  • items:write — read plus create, update, and delete.

A read-only key used on a write request gets back 403. Keys carry the full access of your account, so treat one like a password: keep it out of client-side code and public repos, and revoke it from Settings the moment it leaks.

Base URL and auth

Every route below is relative to this base:

https://hlyxiyvqmfupyqjgfajj.supabase.co/functions/v1/api

Pass your key as a bearer token. No other headers are required beyond Content-Type on requests with a body.

Authorization: Bearer zmk_your_key_here

A missing, malformed, or revoked key returns 401 {"error": "Invalid or missing API key"}.

Endpoints

GET/itemsList items, with filters
GET/todayToday’s items
GET/inboxInbox items
POST/itemsCreate an item
PATCH/items/:idUpdate an item
DELETE/items/:idDelete an item and its subtasks

Reading items

curl -H "Authorization: Bearer zmk_your_key_here" \
  "https://hlyxiyvqmfupyqjgfajj.supabase.co/functions/v1/api/items?dayKey=2026-09-09"

Query parameters on /items:

ParameterMeaning
dayKeyItems scheduled on a date, as YYYY-MM-DD.
inboxtrue for unscheduled items with no list.
latertrue for the Later bucket.
listIdItems in a specific custom list.
completedtrue or false. Omit for both.
limit1–1000. Defaults to 200.
offsetRows to skip. Defaults to 0.

dayKey, inbox, and later pick the container, so only the first one you send is applied — in that order. listId and completed narrow the result further. Archived items and subtasks are never returned; results are ordered the way they appear in the app.

The response wraps the items alongside the paging you asked for:

{
  "items": [
    {
      "id": "V1StGXR8_Z5jdHi6B-myT",
      "type": "task",
      "text": "Write the weekly review",
      "completed": false,
      "dayKey": "2026-09-09",
      "isLater": false,
      "order": 3,
      "isPriority": true,
      "isMediumPriority": false,
      "listId": null,
      "parentId": null,
      "isArchived": false,
      "notes": null,
      "reminderAt": null,
      "createdAt": "2026-09-09T14:02:11.402Z",
      "updatedAt": "2026-09-09T14:02:11.402Z"
    }
  ],
  "limit": 200,
  "offset": 0,
  "hasMore": false
}

Keep requesting the next offset while hasMore is true. Don’t assume a short page means the end — check the flag.

A note on /today

Prefer GET /items?dayKey=<your local date> over GET /today.

The server resolves “today” in UTC, while the app writes each item’s day from your device’s local date. If you are west of UTC, /today starts answering with tomorrow’s list late in the day — from about 5pm Pacific onward. Sending an explicit dayKey avoids the question entirely.

Creating an item

text is the only required field. Send nothing else and the item lands in your Inbox.

curl -X POST \
  -H "Authorization: Bearer zmk_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{"text": "Call the plumber", "dayKey": "2026-09-09", "isPriority": true}' \
  "https://hlyxiyvqmfupyqjgfajj.supabase.co/functions/v1/api/items"
FieldTypeNotes
textstringRequired. Whitespace is trimmed.
typestring"task" (default) or "note".
dayKeystringYYYY-MM-DD to schedule it on a day.
isLaterbooleanPut it in the Later bucket.
listIdstringAdd it to a custom list.
parentIdstringMake it a subtask of another item.
isPrioritybooleanHigh priority.
isMediumPrioritybooleanMedium priority.
notesstringFree-form notes on the item.
reminderAtstringISO 8601 timestamp.

The id and the item’s position are assigned for you — new items go to the end of whichever container they land in. A successful create returns 201 with the finished item:

{ "item": { "id": "kM2p...", "text": "Call the plumber", ... } }

Sending an empty or missing text returns 400 {"error": "text is required"}.

Updating an item

Send only the fields you want to change. Everything writable at creation can be patched, plus order and isArchived.

curl -X PATCH \
  -H "Authorization: Bearer zmk_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{"completed": true}' \
  "https://hlyxiyvqmfupyqjgfajj.supabase.co/functions/v1/api/items/V1StGXR8_Z5jdHi6B-myT"

Setting completed also records the completion time, so the item shows up correctly in your stats. Moving an item is a matter of patching its container: {"dayKey": "2026-09-10"} reschedules it, and {"dayKey": null} sends it back to the Inbox. The updated item comes back in the same { "item": ... } shape; an id that isn’t yours returns 404, and a patch with no recognized fields returns 400.

Deleting an item

curl -X DELETE \
  -H "Authorization: Bearer zmk_your_key_here" \
  "https://hlyxiyvqmfupyqjgfajj.supabase.co/functions/v1/api/items/V1StGXR8_Z5jdHi6B-myT"

Any subtasks are deleted along with the parent. Deletion is permanent — there’s no undo through the API. The response is {"success": true}.

Errors

StatusWhen
400The body is missing something required, or has nothing to change.
401The key is missing, malformed, or revoked.
403A read-only key attempted a write.
404Unknown route, or an item id that isn’t yours.
500Something went wrong on our side.

Errors are always JSON in the shape {"error": "..."}.
